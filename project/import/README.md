# Импорт района Honeymoon

Из каталога `project/` запустите `npm run import:world` для подробного района или
`npm run import:world -- --terrain-radius 32` для района и всех трёх дальних колец.
Импорт работает на Node.js 24 и использует встроенные модули.
Он читает исходные файлы из `../sources/Honeymoon/saves/equestria/` и пишет в
`generated/world/`. Аргументы `--world` и `--out` позволяют указать другие пути.
`--radius 4` означает восемь чанков на сторону. Дальние кольца настраиваются
значениями `--terrain-radius 8`, `16` или `32` при стандартном подробном районе.

## Подробный район

`world.json` содержит включительные границы по блокам, исходный и безопасный
спавн, глобальную палитру и композиции RedPower. Координаты совпадают с Anvil.
Исходный спавн `(-8, 64, -20)` приходится на ячейку пола. Прототип начинает игру
в центре ячейки над ним `(-7.5, 65, -19.5)`.

В `chunks/{x}.{z}.json` координаты заданы в чанках. Для каждой секции `y` — индекс
высоты секции, а `indices` — 4096 индексов палитры в uint16 LE и base64. Порядок
локальных координат определяется формулой `x + 16*z + 256*y`. Сохранённые уровни
`skyLight` и `blockLight` представлены массивами по 2048 байт в base64. В каждом
байте младшие четыре бита соответствуют чётному индексу ячейки.

Стабильные идентификаторы `legacy:<id>:<meta>` и
`cover:<id>:<meta>:<sha256>` сохраняют связь с исходным блоком независимо от
порядка палитры. Нулевой индекс — воздух. Ключ композиции строится по
числовому ID, metadata, типу TileEntity, исходному `cvm` и `cvs`. Слот, материал
и форма каждой детали дублируются в декодированном виде. Префикс `cover:`
включает составные рамы, провода и трубы. Подробный район содержит 4 575
чистых записей состава Covers и 4 669 композиций с учётом остальных типов.

Массивы `objects` и `entities` содержат координаты, идентификатор, тип и
исходные данные NBT. Длинные числа и бинарные массивы кодируются объектами
с полем `$nbt`, чтобы сохранить точность и содержимое. Сохранённые UUID
хешируются при формировании идентификаторов. Исходные NBT-поля всё ещё
присутствуют в данных импорта. Для публичных ответов API нужны только поля,
используемые для игрового представления.

`unknownRegistry` хранит числовые ID и metadata с количеством ячеек и
совпадениями в конфигурации. Для 2240 конфигурация указывает
`DoesNotExsist`, а соответствующие записи NBT содержат `WritingDeskTile`.
Восемь единичных ID Pam совпали с идентификаторами предметов в конфигурации.

`chunkHash` сверяет каждый подробный чанк. `contentHash` идентифицирует
подробную карту с каталогом и метаданными, исключая выбор дальних колец.
Браузер или сервер могут менять собственную регистрацию типов, сохраняя
правки по стабильным ключам.

## Детальное окружение

Импорт с `--terrain-radius` добавляет 80 визуальных чанков до радиуса 6,
включая здания за северной границей района. Они имеют исходные блоки,
микроблоки, объекты и свет. Сервер отдаёт их по тем же адресам, что и
игровые чанки. В манифесте они перечислены отдельно в `visualChunks` и
дополняют палитру после `corePaletteSize`. Игровые границы, исходные
индексы и `contentHash` сохраняются при смене `--visual-radius`.
Дополнительные файлы можно сверить по `visualHash`. Значение 0 отключает
это окружение. Импорт без `--terrain-radius` по умолчанию ограничивается
64 игровыми чанками.

## Дальнее окружение

`terrain-8.json`, `terrain-16.json` и `terrain-32.json` содержат
непересекающиеся кольца. Каждый чанк разбит по высоте на секции.
Каждая секция имеет 64 индекса uint16 LE в base64 в порядке
`x + 4*z + 16*y`. Одна ячейка представляет объём 4 × 4 × 4 исходных блока.
Она отображается при наличии хотя бы трёх учитываемых блоков. Материал
выбирается по частоте. У Covers учитывается материал первой детали,
указанный в палитре как `cover-material:<id>`. Кольца предназначены для
проверки дальнего визуала. Они не используются для столкновений или правок.

| Радиус в чанках | Чанки кольца | Записи состава Covers до этого радиуса | Размер JSON |
| ---: | ---: | ---: | ---: |
| 8 | 112 | 13 675 | 125 980 Б |
| 16 | 768 | 36 552 | 837 824 Б |
| 32 | 3 072 | 54 229 | 3 406 464 Б |

Размеры получены при импорте входного комплекта Honeymoon. Обработка
подробного района и трёх колец заняла около 23 секунд в этом запуске.
