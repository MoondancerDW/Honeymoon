# Проверка Voxelize 3.0.0 на составном блоке Honeymoon

Из каталога `project/` с Node.js 24, `curl` и `tar`

```sh
node qa/voxelize/fetch.mjs
node qa/voxelize/spike.mjs
```

Загрузчик берёт опубликованные пакеты npm `@voxelize/core`,
`@voxelize/wasm-mesher`, `@voxelize/aabb`, `@voxelize/physics-engine` и
`@voxelize/raycast`, все версии 3.0.0, и проверяет закреплённые SHA-512 архивов.
Архивы, распакованные зависимости и `result.json` находятся в
`work/voxelize-spike/`.

`fixture.json` хранит состав одной реальной ячейки Covers из
`(30, 65, -15)`. Если подробный район уже импортирован, добавьте
`--verify-source`, чтобы сверить состав и координаты с `generated/world/`.
Проверка использует функцию построения геометрии проекта для перевода деталей в
четыре параллелепипеда. Их грани переводятся в формат Voxelize с диапазонами UV
общего атласа. Блок помещается в `(4, 4, 4)` в тестовом чанке.

Опубликованный WASM вернул 24 четырёхугольника одной группы с индексами
материалов 209 и 178. Ячейка с ID 65 535 и стадией 5 прочиталась корректно.
Кодирование ID 65 536 дало воздух и сохранило стадию. Удаление ячейки очистило
меш и коллизии, а повторная установка дала тот же меш.

На луче, пересекающем две детали на расстоянии 1 и 1,5 блока, модуль
`raycast` вернул 1,5. Перестановка деталей дала 1. Физический движок
остановил тестовое тело на расстоянии 0,975 блока, что соответствует
первой поверхности с учётом полуширины тела 0,025. Луч вдоль границы
коробки вернул `NaN` в опубликованном `raycast`. Реализация на закреплённой
ревизии обрабатывает нулевые компоненты направления, но всё ещё сохраняет
последнее пересечение внутри ячейки.

Сравнение исходников выполнено для
[`2647e5ea9017ee7a0ce5506144efa03c0b0919f1`](https://github.com/voxelize/voxelize/tree/2647e5ea9017ee7a0ce5506144efa03c0b0919f1).
Результаты получены в Node.js 24.19.0 с опубликованными пакетами. Проверка
изолирует мешинг, попадание луча и коллизию. Сеть, браузер и запись мира в
этом сценарии отсутствуют.
